# SillyTavern Auto Rewrite（正文重写 · 独立版）

让 SillyTavern 在回复生成后再自动（或手动）重写一轮的扩展，**不需要改酒馆本体**，官方原版酒馆直接安装就能用。

## 为什么做这个扩展

很多时候模型第一轮直出容易写歪、台词油腻或者逻辑跟不上，但自己在聊天里手动发一句“重写”又会把废话留在记录里占上下文。

这个扩展把“重写一轮”自动化了：第一版写完后让模型审视前文重来一遍，聊天补全模式直接在原楼生成一个新 Swipe，原稿保留为旧版本。

## 怎么工作的

点输入框顶部的 **「重写正文」**（或打开 **「自动重写」** 开关）后，扩展会等这一轮保存完成，然后在后台按正常对话流程跑一遍重写：

1. 聊天补全模式调用酒馆原生 Swipe 生成，在原楼的新版本中流式显示。初稿与修改意见通过原生聊天内注入，按「assistant 初稿 → user 修改意见」进入 `chatHistory`，不会追加到预设底部控制消息之后，也不新增修改意见楼层。
2. 写完后保留同一消息对象和楼层编号，将原稿与重写稿保存为两个 Swipe，并通知原楼发生了更新／翻页。手动停止时保留已收到的重写正文；未收到正文、报错或聊天切换则恢复原稿。同楼路径也会保存停止时的快照，刷新后可恢复这份重写稿。
3. 若原生工具续传生成了额外中间记录，完成后收回到原楼，并把中间记录归档到重写版本的元数据。非聊天补全及缺少原生接口的旧版酒馆继续使用临时普通对话再合并的兼容路径。

聊天记录里不会多出多余楼层，也不会自己接着触发第三轮。

## 主要功能

- **输入框工具行**：在输入框顶部提供「重写正文」「查看原稿 / 返回重写版」「自动重写」和设置。在原稿和重写版之间切换不会重新请求模型。
- **重写时查看其他版本**：支持此功能的酒馆中，点击「版本」可打开原生版本记录。展开记录可按聊天正文的样式和显示正则阅读。查看期间后台继续生成，关闭后回到当前重写稿。
- **重写进度**：同一行显示阶段和用时，可打开版本记录。在带网络状态的酒馆中，重写请求的接收阶段会显示在这一行。设置弹窗固定外框高度，内容内部滚动。
- **自动重写**：默认关闭；打开后每次新生成回复（包括点右箭头新抽卡）都会自动重写一轮，只翻看已有旧版本不会触发。
- **弹窗设置入口**：点击扩展设置页「正文重写」右侧的「设置」、左下角工具菜单最底部的「重写设置」，或输入框工具行的设置图标，均打开同一个设置弹窗；点击弹窗外空白处即可关闭。
- **自定义修改意见**：可以修改发给模型的重写要求；更新会替换旧版默认意见，保留自己填写的其他意见。
- **修改意见仓库**：保存多个独立条目，按序号从小到大组合。每条可常驻，或绑定多个预设、角色；切换时自动重算生效条目。支持任一绑定匹配、预设与角色同时匹配、复制、停用、删除撤销和 JSON 导入导出。已有单条意见会迁入“常驻修改意见”。
- **原生停止与防丢稿**：按酒馆自带的停止按钮，保留当前已生成的重写稿和上一版原稿；还没收到正文时恢复原稿。停止后不把部分正文标成完整生成；MVU 未完成解析时保留正文并暂沿用本轮初始变量，不继续发起解析请求。
- **重写时更新 MVU 变量（可关闭）**：设置里默认开启，重写稿和首稿一样重新计算变量。关闭后插件不再向模型追加任何变量更新要求，重写稿只替换正文，变量沿用被替换那一版的结果；变量更新块出不出现，由你自己的预设和世界书决定，插件不代为增删。

## 安装方法

在酒馆的 **扩展 → 安装扩展** 中直接填入仓库地址：

```text
https://github.com/wujimol/SillyTavern-Auto-Rewrite
```

或者手动下载源码，将 `index.js`、`revisions.js`、`inplace-rewrite.js`、`background-scheduler.js`、`mvu-compat.js`、`ui.js`、`feedback-library.js`、`feedback-library-ui.js`、`model-routing.js`、`manifest.json`、`style.css` 放到酒馆的第三方扩展目录下，刷新页面即可。

> 如果之前装过旧的定制版，建议先禁用或替换掉旧版，避免两个扩展同时触发。

## 重写模型与 API 配置

修改意见由仓库中当前生效的条目组成。条目序号越小越靠前，同序号按仓库顺序；使用上移、下移按钮可以调整顺序。只拼接条目内容，不自动加标题或改变写作预设的消息结构。每次重写开始时固定本次组合，生成中编辑条目会用于下一次重写。

例如把预设格式设为顺序 1、常驻修改意见设为顺序 2、角色特化设为顺序 3；切换预设或角色后，仅组合当前匹配的格式、常驻及特化条目。预设选择列表只显示当前 API 的预设；切换 API 后可继续绑定其预设，已有绑定会保留。预设按 API 类型和名称绑定，预设改名后需重新绑定；角色按卡片文件标识绑定，通过酒馆改名时会跟随更新。导入采用追加方式，保留已有条目。

新安装启用「默认修改意见」，要求先写约 1500 字分析，再输出完整的新正文。「超长加强版修改意见」单独收录，初始关闭。需要切换时，在修改意见仓库关闭默认条目、启用加强版即可。

在设置里的「重写模型」卡片，选择「沿用当前 API」或酒馆连接管理器中已保存的聊天补全 API 配置，再选择或填写模型型号。型号留空时使用该配置保存的模型；两项都不指定时沿用首轮连接。可以首轮使用 low 型号，第二轮使用另一型号或另一渠道。

输入框支持酒馆已有型号、同一连接保存过的型号及手动输入。打开模型下拉框时，会自动读取所选渠道的模型列表，并直接更新已展开的菜单；同一连接已读取的列表会在当前页面内复用。也可点右侧刷新重新读取；不提供列表的渠道可以直接填写准确型号。列表按连接区分，不把其他自定义端点的列表当作当前端点可用模型。

只临时切换连接参数、模型与请求使用的密钥 ID，不切换目标配置的写作预设、提示词后处理或正则。仍使用酒馆原生生成入口；完成、报错或取消收尾后恢复首轮参数，不轮换服务器默认密钥。运行期间对设置的主动修改会保留；请勿同时用其他扩展发起依赖当前全局连接的后台生成。

支持聊天补全 API（含自定义 OpenAI 兼容、Vertex、Google、Claude 等），不支持文本补全与聊天补全之间跨类型切换。特殊请求头或自定义请求体应保存在连接配置引用的 API 预设中；切到另一自定义地址且没有对应保存数据时，不携带前一地址的请求头和请求体覆盖项。

本次模型选择功能未运行测试、构建、浏览器回归或真实接口验证。

## 使用注意与兼容说明

- **后台标签页**：重写队列使用消息任务调度，后台重试可借助 Worker；不可用时退回普通计时器。切换可见性或恢复页面会重新检查队列并刷新界面。浏览器彻底冻结、丢弃页面或关闭标签时，前端插件仍无法保证继续运行。
- **完成提示**：支持可选的 `st.generation-notifications.sequence.v1` 通知桥接；安装该桥接的酒馆会把首轮与自动重写作为同一轮计时状态，只在最终稿收尾成功后显示完成提示。普通酒馆不需要该桥接即可使用重写。若酒馆本体在后台等待动画帧而未释放生成状态，仍需要修复本体的等待逻辑。

- **插件更新事件**：同楼重写保留原生接收／工具事件，并在最终稿落定后发出原楼的 `MESSAGE_UPDATED` 与 `MESSAGE_SWIPED`，不伪造第二条普通回复。它不会屏蔽首轮完成事件、撤销任意插件已写入的数据，或保证只记录首次正文的插件自动更新；这些插件仍需针对更新／翻页事件适配。
- **请求结构**：使用酒馆已有聊天内注入机制，不直接重排最终 API 数组，不切换写作预设，不屏蔽工具流程。该机制可能与预设已有的同角色、同深度注入合并，或受自定义上下文重组脚本影响，不能保证所有预设行为完全一致。
- **3.3 验证状态**：本轮未运行测试、构建、浏览器回归或真实模型请求。同楼路径需要按实际使用的预设和插件组合确认。

- **MVU 变量兼容**：重写前等待首轮生成和 MVU 额外解析结束，从原回复之前最近的有效楼层快照取得本轮初始变量。第二稿基于该状态生成并更新变量，避免累加首稿变化；原稿与重写稿分别保存对应 Swipe 的变量，取消或刷新中断后恢复原稿变量。启用了 MVU 聊天变量镜像时也同步恢复或切换。若当前页面未启用 MVU（仅聊天历史留有旧变量）或重写稿未触发新的 MVU 变量快照，将保留已生成的重写稿并沿用本轮初始变量，不再丢弃重写正文。
  设置里的「重写时更新 MVU 变量」默认开启，就是上面这套行为。关闭后插件不再向模型追加任何变量更新要求，重写稿只替换正文，变量沿用被替换那一版的结果；变量更新块出不出现，由你自己的预设和世界书决定。
- **其他数据库插件**：普通对话流预设继续走酒馆原生流程。其他插件自行写入的总结、数据库或删除的历史正文不在 MVU 适配的回滚范围内。
- **额度消耗**：每次重写会多发一次模型请求，开启自动重写时单轮会消耗两轮额度。
- **适用范围**：目前只支持单角色聊天；群聊、开场白和纯空白回复不会触发。

MVU 适配根据源码实现，未运行测试、构建、类型检查、lint、浏览器回归或实际接口验证。
为避开 MVU 对消息接收事件的 3 秒节流，紧接首轮结束的重写会短暂显示「等待 MVU 解析窗口」。
