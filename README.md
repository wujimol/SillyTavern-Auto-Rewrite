# SillyTavern Auto Rewrite（正文重写 · 独立版）

让 SillyTavern 在回复生成后再自动（或手动）重写一轮的扩展，**不需要改酒馆本体**，官方原版酒馆直接安装就能用。

## 为什么做这个扩展

很多时候模型第一轮直出容易写歪、台词油腻或者逻辑跟不上，但自己在聊天里手动发一句“重写”又会把废话留在记录里占上下文。

这个扩展把“重写一轮”自动化了：第一版写完后让模型审视原稿，在同一楼生成重写候选；修改意见只进入本次请求，不额外占用聊天楼层。

## 怎么工作的

点正文底部的 **「重写」**（或打开 **「自动」** 开关）后，扩展会等酒馆这一轮生成、保存和翻页完成，再调用酒馆原生 Swipe 入口：

1. 在原回复楼层直接生成一个新的 Swipe 候选，沿用酒馆的预设、世界书、输出正则、流式输出和原生生成事件。
2. 原稿按 assistant 角色、原作者或用户填写的修改意见按 user 角色，通过本次临时提示注入交给模型；不添加额外引导语、标题或包裹标记，原作者默认提示词原文不变。原用户消息及其扩展字段保持在原来的楼层。
3. 完成后直接保留宿主生成的候选，原稿继续作为该楼旧 Swipe，可通过原生翻页或快捷按钮切换。

重写流程不追加临时用户／AI 楼层，不删除临时楼层，也不搬运回复或重新拼接整条消息。扩展只为候选添加自己的版本链接与计时元数据，不复制或还原其他插件的消息字段。

## 主要功能

- **底栏操作条（与翻页胶囊同一行）**：在最新一条角色回复底部提供「重写」「查看原稿 / 返回重写版」「自动」开关和设置入口，在原稿和重写版之间切换不会重新请求模型。
- **稳定的生成状态栏**：重写期间将同一组操作固定在聊天区底部，不随同楼流式正文反复重建；预留对应空间，结束后回到正文底部。设置弹窗固定外框高度，内容内部滚动。
- **自动重写**：默认关闭；打开后每次新生成回复（包括点右箭头新抽卡）都会自动重写一轮，只翻看已有旧版本不会触发。
- **自定义修改意见**：点底栏设置图标或扩展面板里的「正文重写 · 独立版」，可以自己修改发给模型的重写要求。
- **原生停止与防丢稿**：中途按酒馆自带的停止按钮就能取消，失败或取消后通过原生 Swipe 切回原稿，并通过宿主接口清理归属明确的本次未完成候选，不删除聊天楼层；候选归属不明确时保留记录，不猜测删除。

## 安装方法

在酒馆的 **扩展 → 安装扩展** 中直接填入仓库地址：

```text
https://github.com/wujimol/SillyTavern-Auto-Rewrite
```

或者手动下载源码，将 `index.js`、`native-swipe.js`、`revisions.js`、`ui.js`、`model-routing.js`、`manifest.json`、`style.css` 放到酒馆的第三方扩展目录下，刷新页面即可。

> 如果之前装过旧的定制版，建议先禁用或替换掉旧版，避免两个扩展同时触发。

## 重写模型与 API 配置

在设置里的「重写模型」卡片，选择「沿用当前 API」或酒馆连接管理器中已保存的聊天补全 API 配置，再选择或填写模型型号。型号留空时使用该配置保存的模型；两项都不指定时沿用首轮连接。可以首轮使用 low 型号，第二轮使用另一型号或另一渠道。

输入框支持酒馆已有型号、同一连接保存过的型号及手动输入。点右侧刷新，读取所选渠道的模型列表；不提供列表的渠道可以直接填写准确型号。列表按连接区分，不把其他自定义端点的列表当作当前端点可用模型。

只临时切换连接参数、模型与请求使用的密钥 ID，不切换目标配置的写作预设、提示词后处理或正则。仍使用酒馆原生生成入口；完成、报错或取消收尾后恢复首轮参数，不轮换服务器默认密钥。运行期间对设置的主动修改会保留；请勿同时用其他扩展发起依赖当前全局连接的后台生成。

支持聊天补全 API（含自定义 OpenAI 兼容、Vertex、Google、Claude 等），不支持文本补全与聊天补全之间跨类型切换。特殊请求头或自定义请求体应保存在连接配置引用的 API 预设中；切到另一自定义地址且没有对应保存数据时，不携带前一地址的请求头和请求体覆盖项。

模型与连接选择沿用现有路由实现；验证范围见下方。

## 使用注意与兼容说明

- **插件兼容边界**：生成过程走原生 Swipe，其他插件接收到宿主的 `MESSAGE_SWIPED`、`GENERATION_STARTED('swipe')`、`MESSAGE_RECEIVED(id, 'swipe')` 与渲染事件。不会用 `automatic_trigger` 把正文伪装成后台 normal 生成，也不人为重发消息交付事件。原生 Swipe 已有的插件限制仍然存在：例如其他插件的首稿结算、每个候选的数据恢复、仅对 normal 触发的逻辑。此扩展不改写数据库或其他插件来额外解决这些问题。
- **提示词保持范围**：默认提示词和用户保存的修改意见原文不变，原稿仍使用 assistant 角色，修改意见仍使用 user 角色。原生 Swipe 与 normal 的宿主事件、历史处理及提示注入机制有差异；特殊世界书触发、深度正则、思考签名、附件、上下文裁剪和其他插件逻辑不能据此保证与原版逐项一致。
- **生成设置**：尊重当前消息的禁止翻页、循环翻页等设置；不能生成新 Swipe 时明确提示，不临时改动宿主偏好来绕过。只对最新的单角色正文重写，不支持群聊与开场白。
- **工具调用与其他生成**：工具调用如果由宿主扩展为工具记录／后续回复，按宿主自己的流程保留，扩展不会再把这些楼层删除或拼回原楼。无法确认仍属于同楼候选时不会强行覆盖记录。其他扩展并发启动新生成时会释放本次临时提示和模型路由。
- **旧版恢复**：保留旧版临时楼层的中断恢复入口，只用于已有旧版中断记录；新版重写本身不产生这种楼层。
- **额度消耗**：每次重写会多发一次模型请求，开启自动重写时单轮会消耗两轮额度。
- **适用范围**：目前只支持单角色聊天；群聊、开场白和纯空白回复不会触发。

## 本地验证

使用 Node.js 运行定向测试（无外部依赖）：

```sh
node --experimental-vm-modules tests/native-swipe.test.mjs
```

测试使用模拟宿主覆盖同楼 Swipe、事件与楼层数、原字段保留、旧候选重写、自动模式、停止／失败、切聊天、模型路由释放及中断恢复。另在隔离 SillyTavern 1.18 / Chromium 153 中使用合成聊天与模拟模型回复验证非流式／流式、自动改写、停止／失败及存档重开与版本切换。原作者默认修改意见在 none 和 strict 两种设置下，改造前后发送的完整 messages 相同。未验证真实模型渠道、TauriTavern 或所有第三方插件组合。
